# Heating AI

Кліматичний контролер Home Assistant на AppDaemon: інерція теплої підлоги, модуляція котла, денний і нічний комфорт, погода, камін та відключення електрики.

[![Tests](https://github.com/dragonidf/ha-heating-ai/actions/workflows/test.yml/badge.svg)](https://github.com/dragonidf/ha-heating-ai/actions/workflows/test.yml)

## Планування

Спочатку резервується безпечний ранковий нагрів до кінця дозволеного вікна. Додатковий ранній нагрів підтримує нижню температурну межу до ранку. Вночі перевага нижній частині діапазону; вдень можна накопичувати тепло ближче до верхньої. Задані користувачем межі залишаються головними.

Верхня межа, прогноз залишкового прогріву, камін і відключення можуть скасувати небезпечний сеанс. Фактичне тепло оцінюється за підтвердженою електричною потужністю та навченою модуляцією. Обратка — показник запасу тепла, а не температура поверхні підлоги. Майбутній сонячний внесок враховується лише після окремої валідації.

## Встановлення

Тип у HACS: **AppDaemon**, не **Integration**. Докладно: [встановлення, перенесення та відкат](docs/installation.md).

**Статус першої версії:** виправлення встановлене у чинний AppDaemon. Перенесення його робочого шляху на керований HACS-каталог ще потрібно виконати й перевірити. Не запускайте другу копію контролера.

Особисті налаштування та історія залишаються локально. Приклад із вимкненими командами: [heating_climate.yaml.example](examples/heating_climate.yaml.example). Наявні helpers, резервна автоматика та кеш прогнозу погоди є передумовами; HACS їх не створює.

## Розробка

Python 3.12+, AppDaemon 4 для роботи; тести використовують стандартну бібліотеку та імітацію HA без мережі.

```sh
make check test
```

Усі зміни проходять GitHub Actions. Реліз публікується автоматично лише після успішних тестів push у main; для нового релізу змінити VERSION та CHANGELOG.md. Перед встановленням перевірити конкретний commit і результат CI.

Модулі: `heating_model` — модель/план; `heating_stability` — стабільність; `heating_environment` — інерція/зовнішній прогрів; `heating_fallback` та `heating_recovery` — резерв/відновлення; `heating_outages` — графік мережі; `heating_climate` — адаптер HA.
