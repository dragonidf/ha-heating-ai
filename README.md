# Heating AI

Кліматичний контролер Home Assistant: інерція теплої підлоги, модуляція котла, денний і нічний комфорт, погода, камін та відключення електрики. Версія 0.4 переносить чинний V1 з AppDaemon у нативну інтеграцію з оновленнями через Marketplace; особисті датчики й навчена історія імпортуються окремо.

[![Tests](https://github.com/dragonidf/ha-heating-ai/actions/workflows/test.yml/badge.svg)](https://github.com/dragonidf/ha-heating-ai/actions/workflows/test.yml)

## Планування

Фізичний режим котла 3/6/9 кВт або AUTO задається в панелі окремо від HVAC. Вибір описує налаштування на самому котлі й не перемикає обладнання. [Потужність, якість обліку та вентиляція](docs/power-ventilation.md).

Спочатку резервується безпечний ранковий нагрів до кінця дозволеного вікна. Додатковий ранній нагрів підтримує нижню температурну межу до ранку. Вночі перевага нижній частині діапазону; вдень можна накопичувати тепло ближче до верхньої. Задані користувачем межі залишаються головними.

Верхня межа, прогноз залишкового прогріву, камін і відключення можуть скасувати небезпечний сеанс. Фактичне тепло оцінюється за підтвердженою електричною потужністю та навченою модуляцією. Обратка — показник запасу тепла, а не температура поверхні підлоги. Майбутній сонячний внесок враховується лише після окремої валідації.

## Нативна V1+ для Home Assistant Marketplace 2026.11

Пакет `heating_ai_legacy` містить повний V1, його панель, нативні HA таймери,
події та керування обладнанням. AppDaemon у runtime не імпортується.
Фізичне керування доступне після імпорту приватної моделі й історії та
передавання єдиного права команд. Режим спостереження також залишається доступним.

При KWS 190/260 В захист вимикає нагрів на будь-якій фазі при ≤196/≥255 В.
Повернення дозволу потребує 201–250 В на всіх фазах протягом 30 секунд;
далі працюють чинні план, ручні режими й часові захисти V1.

**[Встановлення, перенесення й відкат](docs/marketplace-v1-install.md)**.
Код оновлюється з магазину; приватні дані зберігаються поза каталогом інтеграції.
Для попереднього AppDaemon/HACS-розгортання лишається [архівна інструкція](docs/installation.md).

## Розробка

Python 3.12+, AppDaemon 4 для роботи; тести використовують імітацію HA без мережі. Jinja2 потрібна лише тестам координатора HA, не AppDaemon-застосунку.

```sh
python -m pip install -r tests/requirements.txt
make check test
```

Усі зміни проходять GitHub Actions. Реліз публікується автоматично лише після успішних тестів push у main; для нового релізу змінити VERSION та CHANGELOG.md. Перед встановленням перевірити конкретний commit і результат CI.

## Вебінтерфейс

Три розділи: **Огляд**, **Налаштування**, **Модель і ШІ**. Температура, підтверджена потужність, камін і циркуляція, енергія, добовий прогноз із комфортними межами й відключеннями, погодинні графіки, денний/нічний комфорт, розклад, модуляція котла та журнал рішень. Панель адаптується до екрана й використовує чинну авторизацію HA.

Порівняння температур: **Модель і ШІ → Прогноз і фактична температура → 24 год / 7 днів / 30 днів / Обрати дати**. Пунктир — незмінний завчасний прогноз із фактичною давністю в «Джерелах прогнозу», суцільна лінія — виміри. Прогалини не відновлюються заднім числом. Нижче доступні завершені цикли з початковим планом, актуальною оцінкою, відомим фактом та поясненнями змін. Після оновлення до 0.3.8 один раз перезавантажте відкриту панель: великий архів завантажується сторінками, а не через атрибути Recorder. Деталі перевірки та обмеження: [аудит 01.11.2026](docs/qa-audit-2026-11-01.md).

Після запуску 0.2.0 застосунок встановлює публічні файли інтерфейсу в `www/heating-ai`. Потрібно один раз додати ресурс `/local/heating-ai/loader.js` типу JavaScript module та картку `custom:heating-ai-panel` у панельний dashboard. Його можна закріпити в бічному меню й відкривати ярликом із чинної кліматичної панелі. [Налаштування панелі](docs/web-panel.md).

Оновлення коду й інтерфейсу надходять одним HACS-застосунком; локальний YAML, helpers і навчена модель зберігаються окремо.

Після одноразового підключення [координатора оновлень](docs/automatic-updates.md) достатньо натиснути «Оновити» в HACS: він сам призупинить команди й перезапустить AppDaemon з перевіркою нового циклу. Сам HACS не створює цю автоматику.

Модулі: `heating_model` — модель/план; `heating_stability` — стабільність; `heating_environment` — інерція/зовнішній прогрів; `heating_fallback` та `heating_recovery` — резерв/відновлення; `heating_outages` — графік мережі; `heating_climate` — адаптер HA; `heating_ui` і згенерований `heating_ui_assets` — інтерфейс. Усі дев’ять Python-модулів складають один HACS AppDaemon-застосунок.
