## Правила роботи
- Кожен етап: аудит → зміни → цільові тести → регресії → запис фактичних результатів, SHA, посилань CI, невирішених питань. Статуси: TODO / IN PROGRESS / IMPLEMENTED / VERIFIED / BLOCKED. Не плутати написаний код із перевіреним результатом.
- Один Draft PR, одна узгоджена версія релізу; не merge/publish/install/restart HA без окремого дозволу власника. Не змінювати фізичне керування або конфіг HA у ході read-only аудиту.
- Не послаблювати захисти котла: мережа, напруга, KWS, температура обратки, мінімальні інтервали, зупинка перед відключенням, ручний нагрів та його винятки, auto restore KWS, режими 1–40 кВт, логіка каміна/циркуляції, графік 3.1, чинні entity_id, налаштування/UI, Marketplace. Не створювати зовнішніх AI API, додаткових процесів чи poller-ів.
- Приватні історичні дані не комітити; зберегти backup, схеми, версії, rollback. Не вигадувати вимірювання і не використовувати майбутню погоду в історичному replay. Не видаляти старі дані до перевіреної міграції.
