# Heating AI V1 через Home Assistant 2026.11 Marketplace

## Що саме встановлюється

Marketplace **не підтримує AppDaemon apps**, тому цей реліз є нативною
інтеграцією-пакувальником `heating_ai_legacy` (версія оболонки `1.0.0`).
Після встановлення її файли знаходяться у
`/config/custom_components/heating_ai_legacy/` Home Assistant Core.

Вміст `legacy_app/`: **ті самі дев'ять Python-модулів V1**, файл
`release.json` із SHA-256 та вбудований JavaScript UI через
`heating_ui_assets.py`. Джерело — Git-коміт, який включає виправлення
ручного режиму з PR #24. Версія runtime усередині — `0.3.23`; версія
оболонки — `1.0.0`. Для визначення застосованого виправлення перевіряти
SHA-256 усіх дев'яти модулів, а не тільки номер `0.3.23`.

### Межі гарантій

- Marketplace встановлює / оновлює **файли інтеграції**, а не AppDaemon.
- Інтеграція **не** запускає HeatingClimate, не створює helpers, не
  реєструє керувальних сервісів, не змінює YAML чи дані.
- На існуючому будинку AppDaemon поки працює зі старих посилань
  `.../heating_ai_hacs/*.py` на старий HACS-каталог.
- Щоб новий код почав виконуватися, потрібен **окремий, перевірений
  одноразовий перехід посилань**, після якого оновлення Marketplace
  доставлятимуть нові байти в ті самі цільові шляхи.
- Для оновлень нативної інтеграції Marketplace в HA 2026.11 може вимагати
  перезапуску Core. Не оновлювати кожну дрібну зміну.
- **Не** зупиняти весь AppDaemon / Sky Radar для звичайного оновлення.
  Потрібно окремо узгодити доступний спосіб зупинки лише
  `heating_climate_controller` та перевірити відсутність автоперезапуску
  при зміні посилань.
- Стару автоматизацію `heating_ai_hacs_update_coordinator`, яка
  зупиняє цілий AppDaemon, **не використовувати** для цього релізу.
  Не вмикати її повторно без окремої перевірки.

## Етап I. Доставка файлів (безпечне встановлення)

1. У **Settings → Marketplace → Add from link** вказати
   `https://github.com/dragonidf/ha-heating-ai`. Версія для встановлення:
   **v1.0.0**, тип **integration**. Це не старий AppDaemon-тип.
2. Перевірити, що встановлено саме `heating_ai_legacy` з
   `heating_ai_v1_marketplace.zip`, версія оболонки `1.0.0`.
3. Якщо Home Assistant просить перезапуск Core для першого встановлення
   інтеграції, його виконують **один раз, у погоджене вікно**.
4. На цьому етапі опалення продовжує працювати на старому V1;
   жодної міграції чи зміни автоматики немає.
5. Якщо Marketplace не приймає старий репозиторій через його
   раніше встановлену категорію AppDaemon — **не видаляти та не
   перепризначати діючі файли**. Спочатку повідомити точну помилку;
   потрібен окремий публічний репозиторій лише для інтеграції.

## Етап II. Лише після окремого дозволу: одноразова активація V1

Перевірити read-only:
- Реальний AppDaemon config/apps dir і доступність монтування
  `/homeassistant/custom_components/heating_ai_legacy/legacy_app`
  **саме всередині AppDaemon**, а не тільки у Core.
- Цільова папка містить дев'ять модулів і `release.json`, у ній
  немає приватного YAML або `state.json`.
- Поточні дев'ять посилань ведуть до старого HACS-каталогу;
  немає інших копій HeatingClimate чи дублікатів app YAML.
- Зберегти незалежну резервну копію байтів старих модулів, їхніх
  цілей посилань і поточного app YAML. Не переписувати стан моделі,
  `telemetry.jsonl`, kWh, one-shot чи теплову історію.
- Перевірити owner/ручний режим, armed та роботу
  `heating_watchdog_v1`. **Не** відновлювати HEAT автоматично.
- В окремо погодженому test/maintenance вікні призупинити тільки
  `heating_climate_controller`; довести, що він зупинений і не
  перезапускається від зміни модулів.
- Замінити дев'ять символьних посилань, не створюючи іншого app.yaml
  чи другого writer, з перевіркою SHA-256 кожного цільового файла.
- Увімкнути один існуючий контролер, перевірити свіжий heartbeat,
  `sensor.heating_ui`, кодову версію, усі 9 хешів, AUTO/manual priority,
  теплову модель та монотонність енергії. Поки без нагрівальних команд.
- Якщо перевірка не проходить, відновити **лише вихідні посилання та
  Python-файли**, не відкочуючи дані/сигнали/лічильники.

### Важливо для наступних оновлень

Marketplace може замінити всі файли інтеграції до того, як
AppDaemon встигне завершити поточний цикл. Тому не обіцяти
«автоматичне безперервне оновлення» на цьому етапі. Перед релізом
незалежне оновлення має мати контрольований apply/rollback,
або V1 потрібно ізолювати у власний Supervisor App (Settings → Apps).
Поточна оболонка забезпечує доставку, не атомарне виконання оновлення.

## Повторюваний CI та критерії приймання

- PR #24 включений в SHA релізу, CI V1 повністю зелений.
- `python tools/build_ui.py --check`.
- `python -m unittest tests.test_marketplace_package -v`.
- `python tools/build_marketplace.py --output heating_ai_v1_marketplace.zip`.
- ZIP містить **рівно дев'ять** старих Python-модулів,
  `legacy_app/release.json`, `manifest.json`, `__init__.py`.
- SHA кожного Python файлу тотожний `release.json` та перевіреному
  Git-коміту; ZIP не містить `state.json`, YAML, токенів, телеметрії.
- Встановлення ZIP у ізольованому тестовому HA 2026.11 та
  Marketplace repository detection завершуються успішно.
- Жоден із тестів не надсилає команд до фізичного термостата/вентилятора.
- **Окремо** перевірити staged symlink cutover та відкат без Sky Radar.
  До цього моменту статус лише **ready for package install**, не
  **ready for controller cutover**.
