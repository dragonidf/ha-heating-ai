# План стабілізації V1 після аудиту 0.4.7

Оновлено: 13.11.2026, Europe/Kyiv. Це робочий журнал для продовження іншим GPT/Codex.

## Обмеження

- Не змінювати стан Home Assistant, Recorder або `.storage` з репозиторію.
- Виправлення не повинно вимагати перезапуску HA: Python-зміни мають підхоплюватися
  штатним оновленням/перезавантаженням entry через магазин.
- Не додавати новий polling або окремий фоновий цикл. Recovery має виконуватися
  лише в наявному control tick і тільки коли ledger справді fenced.
- V2 залишається shadow/offline і не стає другим writer фізичних команд.

## Докази, що визначили P0

Під час read-only перевірки live 0.4.7 контролер був у fallback через
`HEAT fenced; external reconciliation required`. Це означає, що ledger захистив
від повторної команди, але recovery не відбувся після помилки під час роботи.
Додаткове опитування HA або важкий перерахунок для цього не потрібні: достатньо
однієї ідемпотентної STOP-команди в уже запланованому 15-секундному control tick.
