# Вебпанель Heating AI

Панель працює всередині Home Assistant. Вона отримує стан через `hass`, використовує чинну авторизацію й змінює лише наявні helpers через офіційні дії HA. Власного токена, окремого сервера чи порту не потрібно. Увімкнення автоматичних команд, одноразовий нагрів і відкат моделі мають підтвердження в інтерфейсі.

## Перше підключення

1. Запустити HACS-версію контролера й перевірити `sensor.heating_ui`: версія `0.2.0`, атрибут `ui_url` — `/heating-ai`. За замовчуванням застосунок записує лише публічні статичні файли у `/homeassistant/www/heating-ai` усередині AppDaemon. Якщо встановлення має інші mounts, задати `ui_www_dir` у локальному YAML. Вимкнути встановлення файлів можна через `ui_enabled: false`.
2. У **Налаштування → Панелі → Ресурси** додати `/local/heating-ai/loader.js` із типом **JavaScript module**. Ресурс додається один раз. Після наступних HACS-оновлень достатньо оновити сторінку: завантажувач читає `version.json` без кешу й імпортує файл з новим хешем.
3. Створити dashboard із URL `heating-ai`, увімкнути показ у бічному меню. Створити один view типу **Панель**, додати ручну картку:

   ```yaml
   type: custom:heating-ai-panel
   ```

   Конфігурація dashboard через API має форму:

   ```json
   {"views":[{"title":"Heating AI","path":"home","type":"panel","cards":[{"type":"custom:heating-ai-panel"}]}]}
   ```

4. Додати на чинну кліматичну панель ярлик із дією переходу до `/heating-ai`. Це відкриває застосунок, а пункт бічного меню закріплює його як окрему панель.

Панель автоматично бере відповідність фізичних датчиків із `sensor.heating_ui.attributes.entities`. Її також можна використовувати з попередньою версією контролера, явно вказавши `entities` у конфігурації картки: `room`, `return`, `outside`, `fan`, `weather`, `energy` та за потреби ідентифікатори helpers. Значення — чинні entity_id, які потрібно прочитати зі свого встановлення. Приклад для іншого будинку не є автоматичним налаштуванням.

Картку можна вбудувати у звичайний dashboard; для повного інтерфейсу рекомендований окремий view типу **Панель**. Темна й світла тема наслідуються від HA. Історичні графіки, погодинна енергія та прогноз погоди — стандартні картки HA; вони потребують доступних джерел і збереженої історії.

## Інформація та керування

| Розділ | Вміст |
|---|---|
| Огляд | Живий стан і причина рішення, комфортні межі, підтверджена потужність, обратка й вулиця, добова енергія й мінімум/максимум температури, 24-годинний прогноз із комфортним діапазоном, нагрів і відключення, ранкові сеанси, умовні інтервали, розподіл енергії, історія температур/мережі/каміна, погодинна енергія, місячний орієнтир, погода |
| Налаштування | Денний і нічний комфорт, час сну, стратегія й дозволені години, енергетичний орієнтир, ліміт сеансу, режим, дозвіл команд, штатний резерв, одноразовий нагрів, керування циркуляцією та нічна швидкість |
| Модель і ШІ | Версія й параметри моделі, точність, придатні проби, навчена модуляція, оцінка запасу тепла, зовнішній прогрів, сонячна валідація, місцева корекція погоди, добовий підсумок із часом оновлення, застосування пропозицій, відкат, heartbeat і журнал рішень |

Невідомі числа показуються як `—`, застарілий прогноз позначається, недоступні helpers неактивні. Обратка залишається показником запасу тепла, а не температурою поверхні підлоги. Фізичні команди котлу й надалі перевіряє контролер із чинними захистами.

## Перевірка інтерфейсу

```sh
make check test
python -m pip install playwright==1.55.0
python -m playwright install chromium
python tools/check_ui_browser.py
```

Браузерні перевірки використовують вигадані дані та імітацію HA. Історичні картки в локальному попередньому перегляді замінено позначеними заглушками; для перевірки Recorder і реальної погоди потрібен запущений HA. Тести не доводять фізичну роботу котла або реле.
