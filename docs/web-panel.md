# Вебпанель Heating AI

Панель працює всередині Home Assistant. Вона отримує стан через `hass`, використовує чинну авторизацію й змінює лише наявні helpers через офіційні дії HA. Власного токена, окремого сервера чи порту не потрібно. Увімкнення автоматичних команд, одноразовий нагрів і відкат моделі мають підтвердження в інтерфейсі.

## Перше підключення

1. Запустити HACS-версію контролера й перевірити `sensor.heating_ui`: версія має відповідати встановленому релізу, атрибут `ui_url` — `/heating-ai`. За замовчуванням застосунок записує лише публічні статичні файли у `/homeassistant/www/heating-ai` усередині AppDaemon. Якщо встановлення має інші mounts, задати `ui_www_dir` у локальному YAML. Вимкнути встановлення файлів можна через `ui_enabled: false`.
2. У **Налаштування → Панелі → Ресурси** додати `/local/heating-ai/loader.js` із типом **JavaScript module**. Ресурс додається один раз. Після наступних HACS-оновлень достатньо оновити сторінку: завантажувач читає `version.json` без кешу й імпортує файл з новим хешем.
3. Створити dashboard із URL `heating-ai`, увімкнути показ у бічному меню. Створити один view типу **Панель**, додати ручну картку:

   ```yaml
   type: custom:heating-ai-panel
   ```

   Конфігурація dashboard через API має форму:

   ```json
   {"views":[{"title":"Heating AI","path":"home","type":"panel","cards":[{"type":"custom:heating-ai-panel"}]}]}
   ```

4. Додати на чинну кліматичну панель ярлик із дією переходу до `/heating-ai`. Це відкриває застосунок, а пункт бічного меню закріплює його як окрему панель.

Панель автоматично бере відповідність фізичних датчиків із `sensor.heating_ui.attributes.entities`. Її також можна використовувати з попередньою версією контролера, явно вказавши `entities` у конфігурації картки: `room`, `return`, `outside`, `fan`, `weather`, `energy` та за потреби ідентифікатори helpers. Значення — чинні entity_id, які потрібно прочитати зі свого встановлення. Приклад для іншого будинку не є автоматичним налаштуванням.

Картку можна вбудувати у звичайний dashboard; для повного інтерфейсу рекомендований окремий view типу **Панель**. Темна й світла тема наслідуються від HA. Графік температур і нагріву читає історію Recorder через авторизований WebSocket HA та малюється у стилі панелі. Погодинна енергія, історія мережі й погода використовують стандартні картки HA. Потрібні доступні джерела та збережена історія.

## Інформація та керування

| Розділ | Вміст |
|---|---|
| Огляд | Живий стан і причина рішення, комфортні межі, камін і циркуляція перед графіками, підтверджена потужність, обратка й вулиця, добова енергія й мінімум/максимум температури, 24-годинний прогноз із комфортним діапазоном, нагрів і відключення, ранкові сеанси, умовні інтервали, розподіл енергії, історія температур/мережі/каміна, погодинна енергія, місячний орієнтир, погода та її ручне оновлення |
| Налаштування | Денний і нічний комфорт, час сну, стратегія й дозволені години, енергетичний орієнтир, ліміт сеансу, режим, дозвіл команд, штатний резерв, одноразовий нагрів, керування циркуляцією та нічна швидкість |
| Модель і ШІ | Версія й параметри моделі, точність, придатні проби, навчена модуляція, оцінка запасу тепла, зовнішній прогрів, сонячна валідація, місцева корекція погоди, добовий підсумок із часом оновлення, застосування пропозицій, відкат, heartbeat і журнал рішень |

Невідомі числа показуються як `—`, застарілий прогноз позначається, недоступні helpers неактивні. Обратка залишається показником запасу тепла, а не температурою поверхні підлоги. Фізичні команди котлу й надалі перевіряє контролер із чинними захистами.

Від 0.2.2 розкладка залежить від фактичної ширини картки, а не вікна браузера. Графік прогнозу зберігає висоту й читабельні підписи на телефоні, перебудовується після повороту чи відкриття бічного меню. Нативні графіки не від’єднуються при кожному оновленні показників. На телефоні температура й комфорт залишаються ліворуч, рішення контролера — праворуч у тому самому блоці.

Від 0.2.3 блок каміна компактний: фаза, температура, різниця з кімнатою та фактична циркуляція. Причину рішення, динаміку й режим можна розгорнути через «Подробиці та налаштування». Розгорнутий блок не закривається при оновленні показників. Кнопка налаштування переходить безпосередньо до циркуляції.

На прогнозному графіку окрема смуга «Камін*» відображає оцінку залишкового тепла за вже чинним законом моделі `exp(-elapsed / 7200)`, поки перепад перевищує 2 °C. Це не прогноз розпалювання або тривалості горіння. Історія температури показує фактичні стани котла й корисного тепла каміна на тій самій часовій шкалі. Від 0.2.4 історія котла також використовує збережені ступені підтвердженої потужності `sensor.heating_boiler_stage`: нічний нагрів видно навіть до появи нового `binary_sensor.heating_boiler_active`. Записів Recorder панель не змінює. Недоступні датчики не позначаються як підтверджене вимкнення. Потужність каміна в кВт не виводиться без калібрування.

На графіку історії доступні 6/12/24 години, коротка легенда з перемиканням кривих, час роботи котла й каміна та перегляд значень дотиком або клавішами ←/→, Home/End. За замовчуванням видно кімнату й обратку; вулицю можна додати натисканням на її показник. Відсутня історія позначена штрихуванням, розриви температур не з’єднуються; неповний підсумок часу позначено `≥` або «неповні дані». Дані кешуються на хвилину, є ручне оновлення й повідомлення про помилку з’єднання.

## Перевірка інтерфейсу

```sh
python -m pip install -r tests/requirements.txt
make check test
python -m pip install playwright==1.55.0
python -m playwright install --with-deps chromium webkit
python tools/check_ui_browser.py
python tools/check_ui_browser.py --browser webkit
```

Браузерні перевірки використовують вигадані дані та імітацію HA. Власний графік історії перевіряється на компактних відповідях Recorder, включно зі старими ступенями котла, відсутніми даними й помилками. Інші нативні картки в локальному попередньому перегляді замінено позначеними заглушками; для перевірки реального Recorder і погоди потрібен запущений HA. Тести не доводять фізичну роботу котла або реле.
