## Specific independence and compatibility contracts
- KWS **A/B/C = boiler phases 1/2/3**. Grid-input sensor naming is reversed: physical 1 = input `voltage_phase_c`, physical 2 = `voltage_phase_b`, physical 3 = `voltage`; do not assume numeric suffixes match physical phases.
- Fresh grid voltage is independent of KWS relay power path. A good grid and NORMAL voltage guard do **not** prove KWS contactor is closed.
- Native controller boot/reload can bring heartbeat back while persistent ledger remains fenced. UI must distinguish actual `heat` confirmation from intended plan, fallback AUTO service return, and KWS power telemetry.
- `sensor.heating_grid` is a summarized state publication, not a raw 15-second heartbeat. An unchanged last_updated of ~11:20 while grid is on is not by itself staleness.
- KWS local `on` state can remain unchanged for hours despite fresh voltage reports. After an outage do not accept the **pre-outage** relay state as post-outage proof. Conversely do not equate no state change with a dead relay.
- Externally exposed HA MCP `last_reported` of unchanged zero phases showed ~13:01 while controller's internal source-quality claimed ~13:39. This may reflect API reporting semantics for same-value refreshes, *not proven spoofing*. Confirm HA Core state.last_reported via controlled test before changing freshness logic.
- Recorder `sensor.heating_controller` has ~8,529 rows per 24h and Deye voltage ~13,321; investigate sampling/cost, but these counts alone do not prove HA slowness was caused by the controller.
